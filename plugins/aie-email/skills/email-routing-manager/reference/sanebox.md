# SaneBox routing notes

Use only when the account actually uses SaneBox. Confirm current settings and account entitlement in its dashboard; do not assume a feature is available because the skill mentions it.

Moving mail between SaneBox folders can train future sorting. Service traffic may have sender-and-subject context, so a dedicated newsletter stream and transaction stream from one business can behave differently. Inspect the exact rule before generalizing a single move. [Official training explanation](https://www.sanebox.com/help/186-how-does-sanebox-determine-trainings).

Disabling a SaneBox folder can move its existing mail back into Inbox. Capture affected IDs and prior state first, let provider reprocessing settle, then reconcile unread and actionable mail without blindly rearchiving the restored set. Enabling a folder can start filtering; a folder named like a SaneBox feature is not necessarily an inert filing destination. [Official folder behavior](https://www.sanebox.com/help/180-how-do-i-add-remove-sane-folders).

For an Inbox-first policy, train account sources to Inbox, keep mixed-purpose traffic visible unless a verified narrower rule works, and use ordinary filing labels after review. Preserve a snapshot of the original training and verify after a fresh dashboard reload. Read-back of settings and observed arrival are different evidence; report both honestly.

Source review: October 5, 2026. Product behavior can change; verify the current live surface before applying a rule.
