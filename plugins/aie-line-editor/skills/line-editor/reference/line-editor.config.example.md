# Optional line-editor project configuration

Copy this file to `line-editor.config.md` in your project directory only if you want explicit house rules. The skill also works with a supplied style sheet or with no configuration. Replace examples with your own choices; they are not universal editing rules.

## Language and mechanics

- English variety: follow the manuscript (for example, British or U.S. English).
- Mechanics reference: name your preferred guide and edition, if any.
- Formatting: preserve the target's front matter, headings, italics, links, and scene breaks.

## Voice and continuity

- Voice samples: identify approved passages or project files, if available.
- Narrative viewpoint and tense: preserve the established choices for each target.
- Continuity notes: identify the project canon or fact ledger, if available.
- Intentional exceptions: list dialect, character-specific usage, spelling, or punctuation to protect.

## House preferences

- Add preferred spellings, terminology, capitalization, and hyphenation.
- List any prohibited wording and context-specific exceptions.
- Explain recurring rhythm or dialogue preferences with short examples.
- Do not impose a numerical quota when an editorial judgment is intended.

## Checks and style-sheet updates

- Identify an existing documented manuscript check, if the project has one.
- Identify the project's living style sheet, if any.
- Default: propose reusable additions in the report. Write to the style sheet only with the author's authorization. Do not store manuscript details in the installed skill folder.
